# Fincz Learn UI/UX Audit

**Review date:** 2026-09-20  
**Environment:** `http://localhost:1313/`  
**Theme:** Hextra  
**Scope:** Homepage, course page, guide page, personal Note page, shared navigation, footer, typography, responsive behavior, accessibility, and visual consistency.

## Executive Summary

The Hextra migration is functional and has a strong foundation: the brand header is visible, the primary information architecture is understandable, the homepage has clear entry points, and the documentation layout is recognizable.

The interface is not yet premium or production-ready. The largest issues are the unbranded Hextra footer, an overly large and repetitive course reading experience, weak footer layout behavior, inconsistent styling layers, and incomplete responsive/accessibility validation.

Fix in this order:

1. Remove all default Hextra branding and correct the footer layout.
2. Reduce course-page title duplication and visual scale.
3. Simplify the documentation sidebar and improve course navigation.
4. Consolidate the CSS architecture and remove legacy Bootstrap styling.
5. Add responsive, focus, reduced-motion, and dark-mode QA before release.

## Priority Guide

- **P0:** Blocks launch or damages trust.
- **P1:** High-impact usability or brand problem.
- **P2:** Noticeable polish, consistency, or accessibility problem.
- **P3:** Enhancement for a later pass.

## P0 Issues

### P0-01: Default Hextra copyright is visible

**Observed:** The live footer displays `© 2026 Hextra Project.` instead of Fincz branding.

**Impact:** This immediately makes the site look unfinished and weakens trust in the learning platform.

**Where:** [config/_default/config.yaml](config/_default/config.yaml#L43-L52), [layouts/partials/custom/footer.html](layouts/partials/custom/footer.html#L1)

**Fix:** Configure the Hextra copyright text or fully override the footer wrapper. The footer should use a Fincz Learn copyright line, current year behavior, and links that match the brand.

### P0-02: Notes privacy state is not represented by the UI or page metadata

**Observed:** Personal Note pages are reachable, which is intentional, but the generated page uses `index, follow` even though the content requests `noindex, nofollow`.

**Impact:** Personal content can be indexed and discovered. This is both an SEO requirement failure and a trust issue for the Notes section.

**Where:** [content/notes/house-construction-guide-and-staircase-plan.md](content/notes/house-construction-guide-and-staircase-plan.md#L10-L12), [content/notes/_index.md](content/notes/_index.md#L1-L5)

**Fix:** Implement a supported Hugo/Hextra robots-meta mechanism and verify generated HTML contains `noindex, nofollow`. Verify Notes are also excluded from sitemap, search data, homepage cards, and section listings.

## P1 Issues

### P1-01: Course title is repeated and visually overwhelming

**Observed:** The Claude Code course page shows the Hextra page title and then repeats a nearly identical title in the content body. The heading scale dominates the first viewport.

**Impact:** The page feels autogenerated, delays access to the actual learning content, and makes the first screen visually noisy.

**Where:** Course frontmatter and body under `content/courses/claude-code/`; shared styling in [layouts/partials/custom/head-end.html](layouts/partials/custom/head-end.html#L14-L27).

**Fix:** Keep one primary H1. Use a shorter page title such as `Claude Code Master Course`, then place the longer promise in a subtitle or lead paragraph. Cap documentation H1 size with a readable `clamp()` scale.

### P1-02: Documentation sidebar is too large for the amount of content shown

**Observed:** The course sidebar exposes many modules and lessons, with long labels wrapping across multiple lines. The page includes an independently scrolling navigation area.

**Impact:** The sidebar competes with the lesson, increases cognitive load, and makes it hard to identify the current position in the course.

**Where:** Hextra navigation generated from [content/courses](content/courses) and the course structure.

**Fix:** Keep only the current course expanded. Collapse unrelated modules by default. Add progress indicators, a clear current-lesson state, and previous/next controls at the bottom of lessons. Consider a course-specific syllabus page instead of exposing every lesson in the global tree.

### P1-03: Footer columns collapse into a long vertical block on a wide viewport

**Observed:** The live footer renders its groups sequentially down the left side with a large unused area to the right. This was visible on the Guide and Note screenshots.

**Impact:** The site looks unfinished and footer scanning becomes unnecessarily long.

**Where:** [layouts/partials/custom/footer.html](layouts/partials/custom/footer.html#L1-L3)

**Fix:** Verify the generated Hextra utility classes are available for custom partials. If they are not, use the theme-supported grid classes or a small custom CSS rule. Confirm a four-column desktop layout, two-column tablet layout, and one-column mobile layout.

### P1-04: Homepage hero is too tall and pushes useful content below the fold

**Observed:** The homepage spends a large first viewport on a centered headline, long supporting copy, three CTAs, and generous spacing before Featured Learning Tracks.

**Impact:** Users must scroll before seeing actual courses. A learning platform should expose the available tracks quickly.

**Where:** [content/_index.md](content/_index.md#L5-L43), [layouts/partials/custom/head-end.html](layouts/partials/custom/head-end.html#L34-L55)

**Fix:** Reduce hero vertical padding, shorten the supporting paragraph, keep one primary CTA and one secondary CTA, and make the first row of learning tracks partially visible in the first viewport.

### P1-05: Homepage card hierarchy is not sufficiently differentiated

**Observed:** Course, guide, and practice entries use similar feature-card treatment. The first row contains large cards with long descriptions but no visible duration, level, lesson count, or completion signal.

**Impact:** Visitors cannot quickly compare what to start with.

**Where:** [content/_index.md](content/_index.md#L45-L88)

**Fix:** Add compact metadata such as `Beginner`, `14 modules`, `Hands-on`, or estimated time. Use a clear visual distinction between Courses, Guides, and Practice without turning every item into a decorative card.

## P2 Issues

### P2-01: Two competing CSS systems remain in the project

**Observed:** The active Hextra implementation uses `hx:` classes and inline styles in `head-end.html`, while [assets/css/custom.css](assets/css/custom.css#L1-L20) still contains Bootstrap-era selectors such as `.top-app-bar`, `[data-bs-theme="dark"]`, and `--bs-card-bg`.

**Impact:** Future changes are unpredictable. Developers may edit styles that are no longer used, and stale rules can become active if an old partial is reintroduced.

**Fix:** Decide on one styling source of truth. Remove unused Bootstrap selectors and variables, or clearly isolate and document any remaining CSS that is still loaded. Keep Hextra overrides in one dedicated file rather than duplicating Google Font imports and button rules.

### P2-02: Google Fonts are imported more than once

**Observed:** Plus Jakarta Sans and JetBrains Mono are loaded in both `head-end.html` and `assets/css/custom.css`.

**Impact:** This creates redundant CSS requests or duplicate declarations and makes typography behavior harder to reason about.

**Where:** [layouts/partials/custom/head-end.html](layouts/partials/custom/head-end.html#L2-L5), [assets/css/custom.css](assets/css/custom.css#L5)

**Fix:** Keep one font loading path. Define the font variables once and use the same variable names throughout the theme overrides.

### P2-03: Typography is oversized on documentation pages

**Observed:** Course and Note H1 headings occupy a large amount of vertical space. Long English and Hindi headings wrap into multiple oversized lines.

**Impact:** Reading starts too far below the navigation and long titles become visually heavier than the content itself.

**Fix:** Use separate type scales for the marketing homepage and documentation pages. Apply a controlled maximum line length and a smaller documentation H1. Test Hindi and English headings independently.

### P2-04: Mixed language typography needs deliberate tuning

**Observed:** Hindi content renders correctly, but the same large font scale is applied to Hindi headings, English headings, and mixed headings containing emoji and Latin text.

**Impact:** Baselines, line breaks, and visual density vary significantly between pages.

**Fix:** Test representative Hindi, English, and mixed-language pages. Set appropriate line height and heading limits. Avoid relying on one Latin-first font stack for all scripts.

### P2-05: Footer text contrast is weak

**Observed:** Footer links appear light gray against a very light gray background in the live screenshots.

**Impact:** Secondary navigation is harder to scan and may fail contrast expectations, especially on low-quality displays.

**Where:** [layouts/partials/custom/footer.html](layouts/partials/custom/footer.html#L8-L14)

**Fix:** Use a darker neutral for footer links and verify normal text contrast in light and dark modes. Preserve a clear hover and keyboard-focus state.

### P2-06: Focus states are not intentionally designed

**Observed:** The custom buttons define hover transitions, but there is no visible custom `:focus-visible` treatment in the custom UI layer.

**Impact:** Keyboard users may lose track of the active control, especially around the pill-shaped CTAs and search control.

**Where:** [layouts/partials/custom/head-end.html](layouts/partials/custom/head-end.html#L82-L123)

**Fix:** Add a consistent, high-contrast `:focus-visible` outline or ring for links, buttons, search, theme controls, and sidebar toggles. Do not remove Hextra’s native focus behavior without replacing it.

### P2-07: Motion is not guarded for reduced-motion users

**Observed:** Feature cards and CTA buttons translate on hover, and the hero badge uses a pulse animation.

**Impact:** Motion can be distracting or uncomfortable for users who request reduced motion.

**Where:** [layouts/partials/custom/head-end.html](layouts/partials/custom/head-end.html#L58-L123), [content/_index.md](content/_index.md#L7)

**Fix:** Add `@media (prefers-reduced-motion: reduce)` to disable transforms, transitions, and pulsing animation.

### P2-08: The homepage color direction is overly blue/purple

**Observed:** Primary actions, hero gradient, hover borders, and background glow all rely on blue and purple.

**Impact:** The interface feels close to a generic AI landing page rather than a distinctive learning product.

**Fix:** Keep blue as the action color but introduce a restrained, intentional secondary palette for course domains. Use color to encode content type, not decoration alone, and confirm dark-mode contrast.

### P2-09: Hero gradient text can reduce readability

**Observed:** The hero relies on `background-clip: text` and transparent text fill.

**Impact:** Gradient text can lose contrast across displays, dark mode, forced colors, and font rendering differences.

**Where:** [layouts/partials/custom/head-end.html](layouts/partials/custom/head-end.html#L27-L32)

**Fix:** Provide a solid-color fallback and test forced-colors/high-contrast mode. Do not make essential meaning depend on the gradient.

### P2-10: Footer lacks a deliberate brand identity block

**Observed:** The footer is mostly link columns and the default theme copyright. There is no short Fincz Learn description, logo treatment, or clear platform statement.

**Impact:** The page ends abruptly and does not reinforce what the platform is.

**Fix:** Add a compact brand block with the Fincz Learn logo, one-sentence description, and a clear legal/support grouping. Keep it uncarded and restrained.

### P2-11: Search is visually prominent but needs interaction QA

**Observed:** Desktop search occupies a large rounded pill in the navbar and displays a `CTRL K` hint.

**Impact:** It is a strong control, but the shortcut, focus state, mobile behavior, empty state, and search-result hierarchy need verification before relying on it as the main discovery tool.

**Fix:** Test mouse, keyboard shortcut, Escape, mobile opening, no-result state, result grouping, and whether personal Notes can appear in search data.

### P2-12: Course and guide pages have limited reading-progress cues

**Observed:** Long course pages rely on the sidebar and browser scroll position. There is no clear progress indicator or lesson completion context in the visible reading area.

**Impact:** Learners may not know how much of a module remains or what to do next.

**Fix:** Add lightweight breadcrumbs, module/lesson context, estimated reading time where reliable, and previous/next navigation. Avoid adding a noisy progress bar unless it is accurate.

## P3 Enhancements

### P3-01: Add intentional empty, loading, and error states

Document expected states for search, missing content, unavailable images, and disabled links. Premium UX includes these states even when the happy path works.

### P3-02: Add a skip link target check

The live page exposes `Skip to content`. Confirm the `#content` target lands at the actual main heading and is not hidden behind the sticky navbar.

### P3-03: Improve link naming consistency

Use consistent labels such as `Explore courses`, `Browse guides`, and `Start practice`. Avoid mixing title case, ampersands, and shorthand such as `Q&A` unless the section vocabulary is intentional.

### P3-04: Avoid relying on emoji for primary visual identity

Emoji in course content can render differently across operating systems and may disrupt heading alignment. Use them as optional accents, not as the only visual cue.

### P3-05: Add visual assets for learning tracks

The homepage is currently almost entirely typography, icons, borders, and gradients. Consider a small, consistent visual language for courses and practice tracks, while keeping documentation pages fast and content-focused.

## Verification Checklist

### Desktop

- [ ] Homepage first viewport shows the brand, clear primary CTA, and part of the first learning-track row.
- [ ] Header, search, and theme controls remain aligned at 1280px and 1440px widths.
- [ ] Footer displays four columns on desktop and no default Hextra text.
- [ ] Course sidebar does not dominate the reading column.
- [ ] Long English, Hindi, and mixed-language headings do not create awkward oversized blocks.

### Mobile

- [ ] Test at 320px, 375px, and 390px widths.
- [ ] Header controls remain reachable without overlap.
- [ ] CTA buttons wrap cleanly and maintain a 44px minimum touch target.
- [ ] Sidebar/menu opens, closes, and returns focus correctly.
- [ ] Tables and code blocks scroll horizontally without breaking the page width.
- [ ] Footer becomes one readable column with reasonable spacing.

### Accessibility

- [ ] Keyboard focus is visible for every interactive control.
- [ ] Reduced-motion mode disables decorative animation.
- [ ] Light and dark mode text contrast is checked.
- [ ] Search has an accessible dialog name and a useful no-results state.
- [ ] The active course/lesson is announced and visually distinct.
- [ ] Heading hierarchy has one meaningful H1 per page.

### Release gate

- [ ] Run `hugo --gc --minify`.
- [ ] Inspect generated HTML for the intended Note robots directive.
- [ ] Confirm Notes are absent from sitemap and search data.
- [ ] Test all footer links with the local server.
- [ ] Re-run browser screenshots at desktop and mobile sizes after fixes.
